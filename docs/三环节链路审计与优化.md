# 文本整理、中文翻译与字幕显示：链路审计与优化

2026-10-18 初稿，2026-10-19 更新。基于已实现的 ASR / 翻译独立队列继续优化，沿用现有本地模型、提示词及音频阈值。以下区分当前行为、已修缺陷与剩余限制。

## 一、目前实际流程

1. ASR 返回后，清理非语音标记与规范已知术语，按原字幕或相邻窗口定位字幕 id；按用户随后替换的 AGENTS.md，先通过质量检查，再发布临时英文。英文仍不等待断句和翻译完成。
2. 质量检查过滤异常重复和不合理长度；有效英文可先显示，随后调整明确问句标点，判断完整句与残句。异常保留未确认原因，不上屏异常原文、不翻译、不标记 Final。
3. 有效文本进入独立翻译队列：完整分句优先复用，新增或修正的分句交给本地模型，中文以累计流式进度返回。需要更多上下文的尾部保持未确认，最多衔接两个相邻音频窗口。
4. 显示层分别跟踪英文、已校验英文、中文及处理完成的修订。新英文及时更新；已有中文在新译文生成期间保留。新的闭合分句完成后，通过已完成单元元数据及时替换未确认尾部，不必等后句全部完成。只有最新识别、完整翻译与音频结束条件一致时才确认整块。

因此，“英文一变就整段重译”“英文总要等断句及翻译完成才显示”“新中文一开始就覆盖旧中文”已不是当前通用流程；但此前实现仍有以下边界缺陷。

## 二、逐环节检查结果

| 环节 | 可复现缺陷或成本 | 本轮处理 | 仍需注意 |
|---|---|---|---|
| 文本整理 | `completePrefix` 与翻译拆句各用一套规则，`U.S.`、省略号可能被误当完整句，引号内句末可能漏掉 | 共用 `sentence-boundaries.ts`，保留原文本偏移、缩写、小数、省略号与引号规则 | 规则断句不是语义理解；不会凭空补齐残句 |
| 中文翻译：重复输入 | 同一句中换行、多余空格使缓存失效 | 缓存键只合并排版空白；英文词、大小写、标点、数字、否定和术语设置仍参与匹配 | 标点或词真正变化仍重新翻译，不模糊猜测 |
| 中文翻译：无效抢占 | 内容未变的 Final 取消同段运行中的 Partial，已算的译文丢弃后重算 | 同源、同术语的 Final 等待正在进行的翻译，再取会话缓存；若此前翻译失败，Final 正常重试 | 文本或术语变化仍抢占；取消后仍等待原生计算退出，避免并发重叠 |
| 字幕显示：旧译文乱序 | 英文数字或否定已修正，旧 MT 回执仍可能写入中文 | 旧 MT 只有对应英文仍是当前英文的完整前缀才可补充显示 | 已显示的中文仍按既定策略保留到新译文到达，期间保持未确认 |
| 字幕显示：数字边界 | `3 → 3.14`、`1 → 1,000` 被字符前缀判断误当追加内容 | 单独保护小数点和千分位内部边界；拦住旧整数译文 | 不把字符前缀等同于语义一致 |

## 三、测试覆盖与证明范围

新增回归先复现句界错切、空白导致重复推理、同源 Final 取消翻译、旧译文覆盖数字/否定修正的问题。独立审查发现数字内部边界缺口后，两例先失败再修复。

边界检查包括：文本变化和术语变化的 Final 仍可抢占、同源 Partial 失败后 Final 重试、有用旧句前缀仍可显示、词内前缀不会被误接受、引号内完整句可先翻译而残句保持未确认。

完整单元、生产构建、桌面/页面回归及同段真实模型结果见 [本轮验证报告](../outputs/pipeline-audit/验证报告.md)。模型、音频和实验输出不提交版本库；在 GitHub 阅读时该本机报告可能不可用。

## 四、剩余优化点与优先级

1. **真实延迟归因。** 已加入音频累计、ASR 排队/推理、MT 排队/首输出、页面更新计时。收音硬件及 AudioWorklet 上游交付延迟尚未测量。下一步用真人课程样本确定累计窗口与 ASR、MT 争用本机资源的成本，不能仅凭调用次数推断体验。
2. **残句上下文。** 当前最多两个窗口，语义未完整时仍可能译得生硬，尤其代词、否定范围、比较和数字。保留失败例，不增加无限衔接，也不拿不完整片段冒充准确句。
3. **未确认中文仍会修正。** ASR 若改词或改标点，对应分句需重译；“保持旧中文直到新结果可用”不等于旧中文始终与最新英文完全一致。Final 不允许回改。
4. **分句完成更新已实现。** 翻译进度携带已完成闭合分句的源文和译文，显示层核对当前英文及修订后更新。重复缓存前缀不会清空旧尾部，字符前缀重合不能冒充完整分句。尚在生成且措辞不同的句子仍保留旧中文，避免从几个字开始覆盖；这部分仍可能等待该句译完。
5. **取消缓存的成本。** 缓存仍按成功完成整轮后提交；取消或后句失败会丢弃本轮新缓存，可能重复计算早先已译的句子。这保留现有失败、取消隔离约束，本轮未改为逐句持久提交。

本轮没有宣称翻译准确率或 1～2 秒体验目标已达标。真人外放课程、轻度噪声、长句和 30～60 分钟持续运行仍须独立验收。

## 五、后续延迟候选验证

本轮测试缩小 Whisper 编码上下文、提前首个 Partial 以及增加 ASR 线程。前两项出现词义风险，后一项没有明确收益，均未启用。按用户替换的 AGENTS.md，实际只恢复原文质量检查前置。结果及复现数据见 [延迟候选验证报告](../outputs/asr-latency/验证报告.md)。

## 六、分句更新与阶段计时（2026-10-19）

用户已确认的第1、2项现已接入。暂停、结束时把当前输入会话的计时保存到 Electron `app.getPath('userData')/diagnostics`；继续使用新会话、新文件。路径由主进程决定；数据只含随机诊断编号、来源、请求/修订/字幕数字编号及阶段耗时，不含音频、字幕或音频会话 token。无请求时不生成文件。关闭或崩溃不保证保存，保存失败不会阻止释放麦克风，诊断读取接口会返回保存错误。

| 指标 | 口径 |
|---|---|
| `audioAccumulationMs` | 当前音频窗口首次能量语音帧至提交样本末尾，包含该窗口尾部静音 |
| `asrQueueMs` | 页面音频片段入队至发出识别调用，不含已丢弃的 Partial |
| `roundTripMs` | 发出识别调用至回执，包含 IPC 与识别处理，不等待完整翻译 |
| `asrMs` / `qualityMs` | 主进程内 ASR 调用、其后快速质量检查耗时 |
| `mtQueueMs` | 进入翻译调度至开始执行；包含等待抢占任务退出等成本 |
| `mtFirstMs` | 翻译开始至首个译文输出，可能缓存命中，不等同于原生模型首 token |
| `mtTotalMs` | 成功完成整轮翻译耗时；失败、取消、拒绝请求不计入 |
| `englishRenderMs` / `chineseRenderMs` | 页面收到有效变化通知至 Vue DOM 更新后下一次 RAF 回调，属于绘制机会，不保证屏幕像素已出现 |
| `speechToEnglishMs` / `speechToChineseMs` | 当前字幕首次能量语音起点至首次原文/中文显示估算；跨窗口衔接沿用字幕原起点，按字幕去重汇总 |
| `speechEndToFinalMs` | 最后能量语音帧至 Final 显示估算 |

主进程与页面各用自身单调时钟，不直接相减不同进程时钟；显示估算将音频采样时长与入队后的页面耗时相加，未包含采集设备和 AudioWorklet 上游交付延迟。没有做人工“首个有效语义”判定，不能当作正式端到端验收。

每项提供样本量、中位数与线性插值 P95，缺失字段表示未测得。主进程最多4096条已接收请求，超过后 `truncated=true`；页面也最多跟踪4096条已入队请求，含后来丢弃的 Partial，因此可能先停止补充显示指标。`truncated=false` 不保证页面指标覆盖所有请求。达到上限后建议暂停再继续，开始新计时文件。

分句提前可见、暂停冻结、文件实际保存及真实模型计时见 [本轮验证报告](../outputs/unit-timings/验证报告.md)。该本机产物默认不提交仓库。
