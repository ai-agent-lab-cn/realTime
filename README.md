# 实译 · Real-time Interpreter

**边听英文，边看中文。一个在本机完成识别与翻译的桌面字幕工具。**

实译面向英文课程、演讲、日常交流与技术内容，通过麦克风接收语音，连续展示英文原文和中文译文，帮助你跟上正在发生的内容。

基于 **Electron + Vue 3 + TypeScript** 构建，使用 **Whisper + Qwen3** 进行本地推理。无需登录，不接入云端识别或翻译 API；工具和模型准备完成后，可离线运行。

> **当前阶段：V0.1 MVP · macOS 优先**
> 已接入本地麦克风、双语字幕和本地历史记录，并提供浏览器模拟演示。识别准确性、字幕延迟与长时间运行仍在优化，暂未提供签名安装包。

## 核心功能

| 功能 | 说明 |
| --- | --- |
| 本地英译中 | 麦克风采集英文语音，在本机识别并翻译 |
| 连续双语字幕 | 原文优先展示，译文随后更新；支持双语或仅中文显示 |
| 临时与确认结果 | Partial 持续更新当前字幕，Final 确认后保持稳定 |
| 断句与衔接 | 根据音量、停顿和文本边界分段，衔接相邻窗口中的明显残句 |
| 播放控制 | 开始、暂停、继续、结束；暂停期间不补录声音 |
| 阅读与复制 | 调整字号、自动滚动，复制单条或全部内容 |
| 轻量术语处理 | 对部分常见技术术语规范表达，保留必要英文 |
| 本地历史记录 | 结束后自动保存本轮 Markdown 双语记录，可打开历史文件夹 |
| 异常提示 | 提示权限、设备、处理失败和积压问题；异常重复结果保持未确认 |

适合在听英文课程、演讲或技术讨论时辅助理解。当前音频入口为**麦克风**，尚不支持直接采集系统声音，也不针对视频平台做专门集成。

## 快速开始

### 1. 获取项目

准备 Node.js **22.12+**、npm 和 Git，然后执行：

```sh
git clone https://github.com/ai-agent-lab-cn/realTime.git
cd realTime
npm ci
```

### 2. 先体验页面

```sh
npm run dev
```

打开 [http://127.0.0.1:5187](http://127.0.0.1:5187)，体验字幕展示、暂停继续、设置和复制等操作。

**浏览器版使用固定模拟数据**，不采集真实音频、不调用本地模型；结束后通过文件下载导出记录。此步骤不需要下载模型。

### 3. 启动桌面本地翻译

当前本地推理链路面向 macOS，已在 Apple M3 / 24GB 上验证。另需准备 **Apple Command Line Tools、Python 3 和 CMake**，并确保 `cmake` 在命令搜索路径中。

```sh
# 编译固定版本的 whisper.cpp 和 llama.cpp
CMAKE_BIN="$(command -v cmake)" sh scripts/local/build_runtime.sh

# 下载模型，支持断点重试与 SHA-256 校验
python3 scripts/local/fetch_models.py

# 构建并启动桌面应用
npm run build
npm start
```

首次安装依赖、获取工具源码和模型需要联网；模型文件合计约 **3GB**，还需为依赖与编译产物预留空间。中国大陆网络下的下载速度与可达性取决于实际网络环境，目前没有离线安装包。准备完成后，日常识别和翻译不需要外网。

桌面开发模式可使用 `npm run dev:desktop`。

### 4. 开始使用

1. 选择“本地麦克风”，点击“开始翻译”，等待模型准备并允许麦克风权限。
2. 播放或说出英文，查看原文与中文逐步更新。
3. 需要暂时离开时点击“暂停”，返回后继续；需要保存本轮记录时点击“结束”。

记录保存在**系统桌面 → 实译历史记录**，每轮一个 Markdown 文件，包含时间、原文、译文与确认状态。清空页面不会删除已保存的历史。

关闭窗口前，请先结束并确认保存成功。结束时仍未完成的字幕保留“未确认”标记，不等待后续译文。应用不保存录音，音频仅在内存中处理；模拟记录会标明数据来源。

## 技术方案

```text
麦克风 Audio Input
    ↓
音频预处理与语音活动检测 VAD
    ↓
增量语音识别 ASR · whisper.cpp
    ↓
断句与相邻片段衔接 Segmentation
    ↓
本地英译中 Translation · llama.cpp
    ↓
轻量术语处理 Terminology Processing
    ↓
双语字幕 Subtitle Rendering → 本地 Markdown 记录
```

| 层级 | 技术 |
| --- | --- |
| 桌面应用 | Electron，受限 preload / IPC 接口 |
| 界面与状态 | Vue 3、TypeScript、Pinia、Vite |
| 音频采集 | Web Audio / AudioWorklet，16kHz 单声道 |
| 语音活动检测 | Silero VAD v5.1.2 |
| 语音识别 | whisper.cpp + 多语言 Whisper small |
| 本地翻译 | llama.cpp + Qwen3-4B-Instruct-2507 Q4_K_M |
| 自动化测试 | Vitest、Playwright、Electron 冒烟测试 |

当前识别采用**累计短窗口增量推理**，并非原生逐词流式 ASR。Qwen 模型使用 lmstudio-community 提供的社区量化版本；模型来源、固定版本与校验值见 [模型准备脚本](scripts/local/fetch_models.py)。

模型服务仅监听本机地址，推理子进程通过网络限制配置禁止访问外网。音频、字幕与历史记录在本机处理，不使用云端 API、账号系统或云同步。

## 开发与测试

| 命令 | 用途 |
| --- | --- |
| `npm run dev` | 浏览器模拟演示 |
| `npm run dev:desktop` | 桌面开发模式 |
| `npm run typecheck` | Vue、TypeScript 与 Electron 类型检查 |
| `npm test` | 状态、字幕、音频分段、队列等逻辑回归 |
| `npm run build` | 类型检查并构建前端与 Electron |
| `npm run test:e2e` | 浏览器模拟操作回归，需安装 Google Chrome |
| `npm run test:electron` | 桌面模拟流程、剪贴板和历史保存检查，需先构建 |
| `npm run test:local` | 固定音频驱动真实本地模型，检查字幕与保存链路 |

真实模型测试需要 macOS 桌面会话、已准备好的模型和运行工具。`test:local` 注入固定合成音频，不采集环境声音；通过模拟或固定文件测试不等于通过真人音频、端到端延迟或长时间运行验收。

### 项目结构

```text
src/            界面、状态与音频采集
public/         AudioWorklet 与静态资源
electron/       桌面接口、本地模型与运行管理
tests/          单元测试与端到端测试
scripts/local/  工具构建、模型下载与本地评测
docs/           产品设计与验证计划
models/         本地模型（不提交 Git）
work/           本地运行工具与临时文件（不提交 Git）
outputs/        本机验证产物（默认不提交 Git）
```

仓库包含源码、测试与准备脚本，不包含模型大文件、运行工具、课程音频和完整本机实验数据。

## 当前限制与后续方向

- **翻译质量**：口音、噪声、手机外放及中英混合可能造成误识别，技术术语也可能出错。重复检测只能拦截部分异常，无法恢复正确原文。
- **字幕体验**：当前断句依赖规则，长句仍可能被切开；实际延迟受硬件、语速和内容影响，尚未达到可统一承诺的延迟指标。
- **运行验收**：真人样本覆盖、30～60 分钟持续运行、真实设备异常与打包权限仍需进一步验证。
- **平台与分发**：暂未验证 Windows / Linux 本地推理，暂无签名安装包；开发目录中的运行资源不能直接作为完整安装包分发。

后续优先完善固定样本评测、识别与翻译质量、字幕断句和稳定性，再推进桌面打包与实机验收。更多版本方向见产品设计文档，均为规划，不代表已经实现。

V0.1 聚焦实时英译中，不包含会议模式、说话人区分、会议纪要、登录、云同步、RAG 或 Agent 扩展能力。
